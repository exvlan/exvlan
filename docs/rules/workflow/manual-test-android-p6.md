# 手测清单：Android（P6 内核库复用）

> 适用：P6 完成后（内核以 `libexvlan_ffi.so` 形式随 APK 打包，UI 通过 C ABI 驱动内核）。
> 目标：确认「实例生命周期 + TUN fd + 事件驱动的路由更新」在 FFI 路径下与原实现等价。

## 0. 准备

- 安装 split-per-abi 中对应你设备的 APK（arm64-v8a 最常见）
- 准备一个可用网络（或配置服务器）
- 保留一份旧版本 APK，便于对比/回退

## 1. 基础

| # | 步骤 | 期望 |
|---|---|---|
| 1.1 | 首次启动 | 授予 VPN 权限后正常进入界面（无「内核未找到」类错误） |
| 1.2 | 新建网络并启动 | 系统通知栏出现 VPN 图标，TUN 建立成功 |
| 1.3 | 查看节点列表 | 能列出对端，延迟/流量有数据 |
| 1.4 | ping 对端虚拟 IP | 通 |

## 2. 事件驱动（P6 重点）

| # | 步骤 | 期望 |
|---|---|---|
| 2.1 | 启动后观察 DHCP 分配 | 拿到虚拟 IP 后 VPN 路由被正确设置（能访问网段内其他设备） |
| 2.2 | 让对端变更代理 CIDR（或重启对端） | 应用内路由随之更新（日志出现 `proxy_cidrs_updated` 处理），无需重启 VPN |
| 2.3 | 断网再恢复 | 实例自动重连，路由不丢 |

> 这两条对应 FFI 新增的 `dhcp_ip_changed` / `proxy_cidrs_updated` 事件转发；若失败，检查 `poll_instance_events` 是否有消费。

## 3. 生命周期

| # | 步骤 | 期望 |
|---|---|---|
| 3.1 | 停止网络 | VPN 图标消失，fd 正确释放 |
| 3.2 | 再次启动同一网络 | 可正常重新建立（不残留旧实例） |
| 3.3 | 同时启动两个网络 | 两个实例并存（或按产品约束给明确提示） |
| 3.4 | 杀进程后重开 app | 不崩溃；VPN 状态与系统一致 |

## 4. 后台与省电

| # | 步骤 | 期望 |
|---|---|---|
| 4.1 | 切到后台 10 分钟 | VPN 保持连接 |
| 4.2 | 息屏 30 分钟后唤醒 | 连接未断（或自动重连成功） |
| 4.3 | 打开「省电模式」 | 明确的可预期行为（不静默断连） |

## 5. 与旧版本对比

| # | 检查 | 期望 |
|---|---|---|
| 5.1 | APK 体积 | split-per-abi 后单包仅多一个 `.so`（约 7 MB） |
| 5.2 | 启动耗时 | 与旧版无显著差异 |
| 5.3 | 内存占用 | 与旧版无显著差异（内核仍在应用进程内） |

## 6. 通过标准

- 第 1/2/3 节全部通过（尤其 **2.2 路由随事件更新**）
- 后台保活与旧版一致
- 无 native crash（`logcat` 中无 `SIGSEGV`/`abort`）

## 7. 已知限制

- 内核 RPC 在 Android 上走 FFI `call_json_rpc`，`api.manage.WebClientService` **未通过 FFI 暴露**；
  若某些「配置服务器远程管理」功能依赖它，需单独确认（见 `mobile-prebuild-kernel.md`）。
- iOS 仍需签名才能验证（NetworkExtension 仅真机）。
