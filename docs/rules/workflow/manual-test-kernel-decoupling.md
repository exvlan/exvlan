# 手测清单：GUI 与内核解耦（发版前必做）

> 适用版本：v26.410.20706 及之后（GUI 不再内置内核运行时，内核改为独立守护进程 + 在线升级）。
> 本轮 CI 已验证「能编译、能打包、包内含内核」，但**运行时行为**只能在真机确认。

## 0. 准备

- macOS：把 `.dmg` 拖进「应用程序」；Windows：运行 `.msi` 安装
- 准备一个可用的网络配置（或从配置服务器同步）
- 记录当前已安装的服务（老用户）：

```bash
# macOS
sudo launchctl print system/era.exvlan.studio 2>/dev/null | grep -E "program|arguments" -A3
# Windows（管理员 PowerShell）
sc.exe qc era.exvlan.studio
```

## 1. 首次安装（关键：应该只弹**一次**密码）

| # | 步骤 | 期望 |
|---|---|---|
| 1.1 | 全新安装后首次打开 GUI | 弹**一次**系统管理员授权（安装内核 + 注册服务） |
| 1.2 | 检查内核落盘 | macOS `/Library/Application Support/exvlan/core/exvlan` 存在且属主 root；Windows `C:\ProgramData\exvlan\core\exvlan.exe` |
| 1.3 | 检查服务指向 | macOS `launchctl print system/...` 的 program 指向**内核路径**，不再是 `EXVlan Studio.app/Contents/MacOS/exvlan-studio` |
| 1.4 | 再次打开 GUI | **不再**弹密码 |
| 1.5 | 重启系统后再打开 | **不再**弹密码（daemon 随系统启动） |

> 老用户：第 1.1 步会额外发生一次「迁移」（旧服务指向 app 二进制 → 重装为指向内核），同样只需一次授权。发版说明需写明。

## 2. 基本功能（normal 模式）

| # | 步骤 | 期望 |
|---|---|---|
| 2.1 | 新建网络并启动 | TUN 建立成功，能 ping 通对端 |
| 2.2 | 查看节点列表 / 路由 | 数据正常，无「RPC 未初始化」类错误 |
| 2.3 | 关闭 GUI | 网络实例随之停止（不驻留） |
| 2.4 | 重新打开 GUI | 配置仍在，可再次启动 |

## 3. 服务模式

| # | 步骤 | 期望 |
|---|---|---|
| 3.1 | 切到「服务模式」并保存 | 若配置未变：**不提权**；若首次配置：一次授权 |
| 3.2 | 关闭 GUI | 网络继续运行（对端仍能连通） |
| 3.3 | 卸载服务 | 弹框询问「保留内核 / 彻底删除」；选择后生效 |

## 4. 内核升级（设置/模式对话框 → 内核面板）

| # | 步骤 | 期望 |
|---|---|---|
| 4.1 | 点「检查更新」 | 显示当前版本 / 最新版本；镜像未同步时提示「更新源尚未同步」而非崩溃 |
| 4.2 | 升级到最新 | 下载 → 校验 → **一次**授权 → 服务自动重启；面板版本号更新 |
| 4.3 | 从历史版本列表选旧版本 | 可回滚；失败时旧内核不受影响 |
| 4.4 | 故意填错更新源 | 报错清晰，不影响在用的内核 |

## 5. 边界与回归

| # | 步骤 | 期望 |
|---|---|---|
| 5.1 | 删除内核目录后打开 GUI | 从随包资源重新安装（一次授权） |
| 5.2 | 断网下打开 GUI | 不阻塞进入界面；升级检查失败仅提示 |
| 5.3 | `getServiceStatus` 异常路径 | 界面显示正确状态（NotInstalled/Stopped/Running） |
| 5.4 | 日志 | GUI 日志写入 app 日志目录；daemon 日志正常 |

## 6. 通过标准

- 第 1 节全部通过（尤其**密码只弹一次**）
- 第 2/3 节功能无回归
- 第 4 节升级与回滚可用
- 无 panic / 无「内核未安装」类误报

## 7. 已知限制（不是 bug）

- 内核 RPC 仅绑 `127.0.0.1` 且**无鉴权**：本机其他用户可控制 daemon（已记录，下个版本处理）
- 移动端（Android/iOS）内核仍随包编译，不支持在线升级
