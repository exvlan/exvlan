# 生命周期矩阵（不变量清单）

> 背景：pre.13–pre.16 的阻断级 bug 有 **一半** 属于「生命周期事件没列全」——
> 只实现了事件的一半（例：会话断开停内核，但会话建立不拉内核）、
> 或者让"瞬时状态"触发了终止（例：实例数归零 → 内核退出）。
>
> 这份表是**审查清单**：任何改动涉及下列对象或事件，必须逐行对照。

## 对象

| 对象                 | 持有者                                                         | 说明                                                 |
| -------------------- | -------------------------------------------------------------- | ---------------------------------------------------- |
| 内核进程（`exvlan`） | `exvlan-service`（service）/ systemd 或 GUI supervisor（core） | 有 TUN、监听 peer 端口与 RPC portal                  |
| 网络实例             | 内核（`--config-dir` 下的 `*.toml`）                           | 一个实例一块 TUN                                     |
| 会话（session）      | 服务（**发过 `hello` 的** IPC 连接计数）                       | `policy=session` 的存活锚点                          |
| 热点代理流（NAT）    | 内核                                                           | TCP 代理（含远程管理的 RPC 端口）                    |
| gateway              | `exvlan-gateway`（服务降权拉起）                               | 控制面 HTTP/WS，仅回环                               |
| 迁移标记             | `<user>/migrate.done.v3`                                       | 一次性迁移是否已完成（旧版本标记一律视为「未完成」） |

## 事件 × 期望

| 事件                                | 内核                                  | 实例                     | 会话 | 期望行为                                                          | 反例（历史 bug）                                     |
| ----------------------------------- | ------------------------------------- | ------------------------ | ---- | ----------------------------------------------------------------- | ---------------------------------------------------- |
| 服务启动（`boot`）                  | 按 `policy` 决定是否拉起              | 由内核从 config-dir 恢复 | 0    | `resident` → 拉起内核；`session`/`stopped` → 不拉                 | —                                                    |
| 首个会话 hello（`session_open`）    | 若无则**后台**拉起                    | —                        | 1    | 只有 `hello` 才算会话，一次性命令不计数                           | pre.16：只加计数不拉内核（#58/#60）                  |
| 最后一个会话断开（`session_close`） | `policy=session` 时停                 | —                        | 0    | `resident` **不**停；`cli config list` 这类短连接不再停内核       | 重启服务时把内核停掉（#66）                          |
| 配置下发（热字段）                  | 不变                                  | 热更新                   | 不变 | 不断流                                                            | —                                                    |
| 配置下发（非热字段）                | 不变                                  | 停旧 → 起新              | 不变 | 执行期间**禁止** `session_close` 停机；实例数归零不得导致进程退出 | pre.16：无 `--daemon` → 内核静默退出（#68）          |
| 删除最后一个网络                    | 必须存活                              | 0                        | —    | 继续提供服务（列表为空）                                          | 同上                                                 |
| 换内核（apply）                     | 停旧 → 清残留（`.prev`）→ 替换 → 起   | 重建                     | 不变 | 启动后校验「应答者 pid == 刚拉起的 pid」                          | pre.16：旧内核被改名 `.prev` 却继续占端口（#62/#63） |
| 内核无响应                          | 连续 N 次探活失败 → 原子重启          | 重建                     | 不变 | 不需要用户点「重装服务」                                          | pre.16：只能重装                                     |
| 界面退出（GUI quit）                | `resident` 不停 / `session` 停        | 跟随内核                 | 0    | —                                                                 | —                                                    |
| 系统重启                            | launchd/SCM/systemd 拉起服务 → `boot` | 恢复                     | 0    | `resident` 自动有内核                                             | pre.16：卡在 `Normal` 不拉（#58）                    |
| 服务自更新                          | 服务重启 → `boot`                     | 恢复                     | 0    | 版本文件与新二进制一致                                            | pre.15：反复重装                                     |
| 迁移（一次性）                      | 停                                    | 转换后恢复               | 0    | 失败停在错误页、不写标记                                          | —                                                    |

## 三条硬约束

1. **瞬时状态不得终止长期对象**：实例数归零、会话归零、端口短暂不可用 —— 都不能让内核/服务退出（`--daemon` + `restarting` 标记）。
2. **每个「停」都要有对应的「起」**：会话断开停内核 → 会话建立必须拉起；界面退出停内核 → 界面启动必须拉起；服务重启不拉 → 启动后必须 `ensure`。
3. **唯一决策者**：起停/策略/版本/端口由服务决定；GUI、CLI、gateway 只发意图（`policy`/`desired`），不自己判断。

## 已知的"预期异常"

- `enable_kcp_proxy` / `enable_quic_proxy` 开启时，**跨节点的 RPC portal 不可达**：
  客户端会把到对端 RPC 端口的 TCP 代理流包进 KCP/QUIC，而
  `wrapped_transport_destination` 遇到「目标是自己的监听端口」会直接忽略（防环路）。
  这是内核行为，不是网络问题；产品默认关闭这两个开关，并在 UI 上标注。
