## 2. 依赖安全治理（本轮新增）

### 2.1 CI 依赖审计门禁

- **workflow**：`.github/workflows/audit.yml`（`cargo audit` + `pnpm audit --prod`，root 与 sdk）。
- **触发**：PR 全量、tag 全量、`workflow_dispatch` 全量、push 按 `deps` 路径门控，**外加每周一 03:00 UTC 定时**（`pipeline.yml` 的 `schedule`，该事件只跑 audit）。
- **允许清单**：`.cargo/audit.toml`（`[advisories].ignore`）+ 元数据 `.cargo/audit-allowlist.toml`（`id`/`review_by`/`reason`）。
  - `script/check_audit_allowlist.py` 在 CI 里先跑：**过期即失败**，且两处 id 集合必须一致。
  - 当前 3 条：`RUSTSEC-2023-0071`（rsa）、`RUSTSEC-2026-0118/0119`（hickory-proto），`review_by = 2027-01-31`。
- **范围取舍**：只阻塞**生产依赖**（`--prod`）；dev/build 链交给 Dependabot 与 issue 跟踪。

## 6. 踩坑记录（已写入技能）

1. `vp check --fix`（预提交）会把 `.json5` **反引用化** → `jq` 解析失败；已在 `vite.config.ts` 用 `fmt.ignorePatterns: ['**/*.json5']` 排除。
2. `cargo-audit 0.22` 只读 **`.cargo/audit.toml`**（根 `audit.toml` 无效）。
3. 本地 npmmirror **无 audit 端点** → 审计命令要显式 `--registry https://registry.npmjs.org`。
4. `protoc` 复合 action 必须按 **OS×arch** 选资产（曾硬编码 `linux-x86_64` 导致 macOS/Windows/aarch64 全红）。
5. `skip-duplicate-actions` 的 `cancel_others` 会取消同分支较早运行 —— 连续 push 时只有最后一次完整跑。
6. Go module tag 经 proxy/sumdb 后**不可变**，不要为对齐 release 而移动。
